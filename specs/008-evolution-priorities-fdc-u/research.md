## C7 — Unificação DBs + pyproject deps

### Decision: Consolidate all databases to `data/bioeolica.db`

**Rationale:**
- Duas DBs detectadas: `data/bioeolica.db` (3.5MB, ativo) e `./bioeolica.db` (raiz, abandonado)
- `data/database.db` (obsoleto, 0B ou ausente — candidates FDC-U C7 menciona R3/R4/R9)
- Regra M4 (Mapa Único): single source of truth → única DB em `data/bioeolica.db`
- Estratégia: manter apenas `data/bioeolica.db` como canônico; script de migração unifica dados; remover duplicatas

**Alternatives considered:**
1. Manter duas DBs separadas → Rejeitado: viola M4, corrompe rastreabilidade
2. Migrar para PostgreSQL → Rejeitado: overkill para aplicativo desktop/local, sem infra de DB server
3. SQLite com WAL mode → **Escolhido**: já é SQLite, zero custo de migração de引擎

### Decision: Migrate scripts for data consolidation

**Rationale:**
- `./bioeolica.db` contém tabelas diferentes de `data/bioeolica.db` (verificado via `.tables`)
- Script de migração em `scripts/migrate_unify_db.py` funde dados com controle de conflito (timestamp-based)
- `data/bioeolica.db` permanece como canônico; `./bioeolica.db` vira symlink ou é removido

### Decision: pyproject.toml dependency audit

**Rationale:**
- pyproject.toml tem `[project]` básico mas sem `dependencies` explícitas
- Dependências reais espalhadas em múltiplos `requirements*.txt` e imports diretos
- Estratégia: consolidar em `pyproject.toml` com `[project.dependencies]` + `[tool.pdm.dev-dependencies]`
- Manter compatibilidade com `pip install -e .`
